# Golden Sets

Labeled evaluation sets for LifeOS/Axi model benchmarking. All files are JSONL;
lines starting with `//` or `#` are comments (every loader skips them). All
natural-language content is Spanish (Axi's production language) except code
snippets, which stay in their source language.

| File | Cases | Consumed by | Purpose |
| --- | --- | --- | --- |
| `brain_quality.jsonl` | 35 | `cpu_sweep.check_deterministic` + `subjective_judge` (via `bench_model.py` / `model_audit.py` brain role) | Big-brain conversational quality: deterministic checks + 6 rubric cases judged by the prod 35B. See `brain_quality_README.md` for the check-field schema. |
| `extraction_quality.jsonl` | 69 | `lifeos.agents.eval.scoring.score_extraction` (extraction role) | Nano entity-extraction: per-field accuracy + case pass rate. |
| `domain_classification.jsonl` | ~60 | `lifeos.agents.eval.scoring.score_by_layer` (`_run_eval.py`, `model_audit.py` domain role) | Nano domain classifier, segmented by production layer (`nano` / `regex` / `guard`). |
| `tool_calling.jsonl` | 12 | `model_audit.py` toolcall role | OpenAI-style tool calling mirroring Axi's whitelisted web-search flow. 9 cases expect a specific call (`web_search`, `create_reminder`, `get_health_summary`), 3 chit-chat cases expect NO call (false-call trap). Schema: `{id, messages, tools (name list; full JSON schemas live in model_audit.py TOOL_SCHEMAS), expect: {tool: name|null, arg_substrings: {arg: [substrings]}}}`. Metrics: correct-tool rate, arg accuracy, false-call rate. |

Schema: `{id, image, question, must_contain: [[alternatives...]]}` — every group must be satisfied by one alternative, case/accent-insensitive. Assets regenerate via `model_audit.py`'s `ensure_vision_assets()`. |
| `code_review.jsonl` | 8 | `model_audit.py` codereview role | Code review (VT-3B's role): 7 short Python/Dart snippets each with one planted bug (off-by-one, SQL injection, resource leak, None-deref, mutable default, race condition, zero-division) scored by bug-keyword hits, plus 1 clean snippet scored for false positives (model must answer `SIN BUGS`). |
| `code_generation.jsonl` | 8 | `model_audit.py` codegen role | Code generation (the 35B's nightly self-development role): Spanish prompts in the dev-director instruction style ask for one small pure-Python function/class each (string parsing, dates, lists, a class, a regex task, edge-case handling). The harness EXECUTES the generated code: extracts the ```` ```python ```` block (raw-text fallback), injects asserts, and runs it in an isolated subprocess (`python -I -c`, minimal env, temp-dir cwd, hard timeout with process-group kill — never `exec()` in-process). Schema: `{id, prompt, function_name, tests: [{args, kwargs?, expected}], timeout_s}` — pass = every `function_name(*args, **kwargs) == expected`. Metrics: `{n, pass_rate, compile_rate, failed_ids}`. |
| `records_qa.jsonl` | 10 | `model_audit.py` recordsqa role | Grounded personal-records QA mirroring `domain_chat._build_query_system`: synthetic dated ES record rows in the system prompt, question in the user turn. 7 answerable cases + 3 anti-fabrication traps (`refusal_expected`: the reply must refuse in a no-tengo-registro style). Schema: `{id, domain, today, records_block, question, expected: {must_contain: [[alternatives...]], must_not_contain_numbers_absent_from_records, refusal_expected?}}`. Deterministic scoring: any-of `must_contain` groups + fabricated-number detector (any number token in the reply absent from records_block+question fails; integers 0-10 and question-mentioned years tolerated). Metrics: `{n, pass_rate, fabrication_rate, failed_ids}`. |
| `digest_narration.jsonl` | 8 | `model_audit.py` narration role | Daily-digest narration mirroring `dashboard._DIGEST_NARRATOR_SYSTEM`: facts with exact counts/amounts/dates in, 4-6 warm ES sentences out. Deterministic scoring: EVERY numeric token from `facts_text` must appear in the reply, NO fabricated numbers (same tolerance as records_qa), sentence count within `constraints`, Spanish check. Plus a per-case warmth rubric judged by the prod 35B when healthy (reuses the conversation role's rubric-judge; judge-absent → note). Schema: `{id, facts_text, constraints: {min_sentences, max_sentences}, rubric}`. Metrics: `{n, numeric_fidelity_rate, structure_rate, judge_score?, note?, failed_ids}`. |
| `long_summarization.jsonl` | 6 | `model_audit.py` longsum role | Long-context summarization mirroring `meeting._hierarchical_summary` (window pass + executive pass with the mandated `##` section headers) and `chat_archive._SUMMARY_SYSTEM`. Schema: `{id, kind: meeting_window|executive|chat_archive, transcript, planted_atoms: [{label, must_contain_any}], required_sections? (executive only)}`. Deterministic scoring: atom recall + executive section-structure validation + fabricated-number detector. Cases whose prompt exceeds `ctx*3` chars are skipped with a note. Metrics: `{n, atom_recall, structure_rate, pass_rate, failed_ids, skipped_ids?, note?}`. |
| `structured_parsing.jsonl` | 14 | `model_audit.py` parsejson role | Strict JSON/label parsing fallbacks across 5 production contracts: `when` (`reminder_brain.parse_when_brain` → `{"when_iso": ...|null}`), `schedule` (`reminder_brain.parse_reminder_brain` scheduling-intent JSON), `voice_intent` (`intents._brain_classify` fixed-label set), `graph_facts` (`extractor.extract_and_store` → `{"facts": [...], "relations": [...]}`), `coreference` (`identity._llm_same_entity` → si/no). Systems are baked with a FIXED now (2026-07-15T10:00 CDMX) so expectations stay deterministic. 5 negative traps (non-temporal → null, chit-chat → not-a-reminder/dictation, ephemeral → empty facts, non-coreferent → no) that count DOUBLE in `failed_ids`. | `agentic_research.jsonl` | 5 | `model_audit.py` agentic role | Multi-round agentic research mirroring `axi.briefing.run_agentic_briefing`: the harness drives a REAL tool loop against the candidate — offers `web_search` + `web_fetch` (OpenAI schemas), executes CANNED handlers when the model calls them (planted snippets / page texts), feeds results back as `role=tool` messages, caps at 5 tool rounds, then drops the tools and forces a final JSON synthesis (mirrors `_FINAL_SYNTHESIS_PROMPT`). Schema: `{id, prompt (ES briefing task), canned_tools: {web_search: {query_must_mention, results}, web_fetch: {url: page_text}}, expected: {must_call_tools, final_json_keys: [title, summary, items, markdown], facts_must_appear}}`. Deterministic scoring: required tools called (+ query discipline), rounds ≤ 5, JSON validity/keys, planted-fact recall. Metrics: `{n, pass_rate, tool_correct_rate, json_valid_rate, mean_rounds, failed_ids}`. |

Schema: `{id, kind: thought\|elicitation, context_block, max_chars, expected: {sentinel_expected, sentinel, topic_must_mention_any?}}`. Metrics: `{n, restraint_rate, speak_pass_rate, pass_rate, failed_ids}`. |
| `vision_classification.jsonl` | 6 | `model_audit.py` visionclass role (requires `--mmproj`) | Structured vision classification mirroring `lifeos.posture.analyze` (`_PROMPT_ES`, strict JSON `{state, confidence, suggestion}`). Deterministic PIL stick-figure desk scenes in `vision_assets/posture_*.png` (generated by `model_audit.ensure_posture_assets()`): upright, slouched (curved spine + dropped head), forward head, leaning, empty chair, second upright. Scoring: JSON validity + label accuracy over the fixed 6-state set + confidence ∈ [0,1] + suggestion empty/short for `good`/`not_at_desk` (≤ 100 chars otherwise). Skips with a note without `--mmproj`. Schema: `{id, image, labels, expected_label, json_contract: {keys}}`. Metrics: `{n, label_accuracy, json_valid_rate, pass_rate, failed_ids}`. |
| `dev_planning.jsonl` | 8 | `model_audit.py` devplan role | Self-development director role (VT-3B in `axi.dev_director`), ENGLISH prompts mirroring the production `_DIRECTOR_SYSTEM` / `_REVIEWER_SYSTEM`. 3 `instruction` cases (goal → ONE actionable coding instruction) scored by deterministic keyword classes (concrete file/function target, expected behavior, tests/edge cases) + length cap, plus an optional actionability rubric judged by the prod 35B when healthy. 5 `review` cases (goal + small unified diff + tests_output → `DONE`/`NOT DONE`, production verdict parser): 2 complete diffs (DONE) and 3 under-implemented/broken diffs (NOT DONE), scored against `satisfies`. Schema: `{id, kind, goal, max_chars?/rubric? (instruction), diff/tests_output/satisfies (review)}`. Metrics: `{n, instruction_pass_rate, review_accuracy, pass_rate, judge_score?, note?, failed_ids}`. |
| `conversation_quality.jsonl` | 8 | `model_audit.py` conversation role | Is Axi PLEASANT to talk to? Single-turn empathy, multi-turn coherence (last user turn references earlier context), small-talk warmth, follow-up-question quality, and one long-rambling-user case (concise-but-warm summarizing). Schema: `{id, messages: [...], rubric: {criteria: [{name, weight, description}]}}` (weights sum to 1.0; the last turn is always the user). The candidate's reply is judged by the prod 35B (port 8080) against the case's OWN rubric; judge unhealthy → judge layer skipped with a recorded note. Two deterministic judge-free checks always run: reply is Spanish (`cpu_sweep.is_spanish`) and non-empty under a sane length. Metrics: `{n, judge_score (weighted 0-1, null when skipped), spanish_rate, sane_rate, note?}`. |

## Conventions

- **Any-of groups**: where a schema uses `must_contain: [[...], [...]]`, the outer
  list is AND, the inner list is OR. Matching is lowercase and accent-stripped.
- **No-call / clean trap cases** exist in `tool_calling.jsonl` and
  `code_review.jsonl` so over-eager models pay for hallucinated calls/bugs.
- Sets are versioned by their header comment; append cases rather than mutating
  existing ids so historical registry rows stay comparable.

# F1 — listening placement source repair

## Observed device defect and scope

Phase A on TEST Pixel 0.20.0/1017 established that `Comprobar` revealed the sentence and a 0% score without pressing `Escuchar`, both with an empty answer and with `qa`. The second-listen capture was inconclusive; it did not establish that audio worked. This change repairs only the listening placement screen, its widget tests and its English/Spanish localization. It does not alter placement thresholds, repository implementation, downloaded voices or the separate F2 voice-adapter work.

## Behavior

- Listen starts a busy state immediately. A second tap cannot start another stream. A play counts only after the one-sentence speaker stream completes normally; failed synthesis/playback and route exit do not count. Each sentence permits two successful plays. Failed playback shows the existing localized read-aloud error and keeps Listen available for retry.
- Check requires completed playback and non-whitespace input. Only after completed playback can the learner choose `No lo entendí` / `I did not understand` to record an explicit zero without guessing words. Check/Next are guarded against duplicate submission; the keyboard is dismissed on submission.
- The final result is hidden while saving and if saving fails. An explicit localized retry attempts the save again; the result and activity completion appear only after save succeeds. Route exit stops playback and asynchronous continuations guard unmounted state. The existing level calculation and local repository remain unchanged.

They do not establish real acoustic playback, audio quality, native engine stability, on-device keyboard layout or persisted device state. F2's voice adapter remains unverified on Pixel. No device, build, install, publication or user history operation was performed. Full device playback and placement journey must be rerun by the device controller after an authorized candidate build/install; the phase-A blank/`qa` attempt records remain intact.

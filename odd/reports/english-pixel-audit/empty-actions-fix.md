## Separate read-only reminder diagnosis (not part of this repair)

The picker seam in `english_providers.dart` calls Flutter `showTimePicker` with initial `TimeOfDay(hour: 20, minute: 0)`. The reminder tile formats the *returned* time as 24-hour text for display; it does not convert the chosen hour. In the devbox Flutter SDK `packages/flutter/lib/src/material/time_picker.dart`, `_parseHour` (lines ~1775–1797) interprets a typed 1–12 hour using the current AM/PM period unless `MediaQuery.alwaysUse24HourFormat` is true. With the initial 20:00 (PM), entering `04:37` in a 12-hour picker yields 16:37 if PM was never toggled. This matches the Phase E observation, but device AM/PM and MediaQuery state were not independently captured; the device controller is rechecking it. The existing reminder widget test overrides the picker and therefore cannot distinguish its real 12-hour/24-hour behavior. Minimal proposed test, **only if separately authorized**: a real `showTimePicker` widget test with Spanish locale and explicit `alwaysUse24HourFormat` false/true, initial 20:00, keyboard entry `04:37`, AM/PM selection, and assertion on returned `TimeOfDay`; pair with the device controller's visible-period readback. No reminder or hub source was edited here.

## Remediation (not yet installed on Pixel)

The former guard rejected missing `sample_rate` but could not restore audio and missed other fatal native metadata requirements. Upstream sherpa-onnx **v1.13.4** `offline-tts-vits-model.cc` requires `sample_rate`, `n_speakers`, `language`, `comment`; `comment=piper` controls the Piper input path. The same version's `scripts/piper/add_meta_data.py` specifies the compatible metadata set. Source: `https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.4/sherpa-onnx/csrc/offline-tts-vits-model.cc` and `https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.4/scripts/piper/add_meta_data.py` (parent-verified).

`piper_model_metadata.dart` now parses top-level ONNX ModelProto `metadata_props` (field 14), streaming past graph weights. It validates the complete native-critical metadata set and conflicts against the **paired** Piper JSON. For missing fields, it appends converter-compatible metadata to an app-local derivative of the **same original model bytes**. JSON must say espeak, one speaker, supported English/Spanish language family, valid sample rate and matching espeak language; unknown or conflicting data fails catchably **before FFI**. English/Spanish language names come from verified JSON locale families, not the currently selected Axi voice. `22500 → 22050` follows upstream conversion. Existing compatible converted models remain unchanged, including official older models that repeat identical metadata and omit optional `version`/`has_g2pw`; conflicting duplicates are rejected.

Cache name fingerprints original model **bytes** plus paired JSON and adapter version; a changed source (even same length) or config gets a new derivative. A temporary, unique per-isolate file is flushed and atomically renamed after metadata/length verification. Concurrent preparations were tested; partial/corrupt cached outputs are rebuilt. A legal 10-byte protobuf int64 field is skipped correctly. No original model, tokens, espeak data, catalog selection, host or service was changed. The synthesizer requires its original paired JSON, token table and espeak marker before native initialization. First use temporarily needs space for one additional model copy and two sequential streaming hash passes; subsequent sentences re-hash but do **not** recopy. Old content-addressed derivatives are not silently deleted after source changes; space reclamation policy remains a follow-up.
